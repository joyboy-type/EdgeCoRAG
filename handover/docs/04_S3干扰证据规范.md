## 1. 实验条件（沿用你的定义）

| 条件 | 含义 | 证据来源 | 是否 Oracle |
|---|---|---|---|

## 2. ⚠️ 一个对我们非常有利的实测事实

我逐题比对过全量 1,353 题：

> **756 / 1353 = 55.9%** 的题目，官方 `retrieved_images` 中**已含至少 1 张 GT 正确证据**。

**对 S1 是坏消息**（官方池不干净，见 `03_证据规则.md` §3）。
**对 S3 是好消息**：因为我们**确切知道哪些图是 GT**（内容 sha256 可比），
所以「构造一个**保证不含正确证据**的干扰集」是**可自动校验、可复现**的，
而不是靠人工肉眼判断。这一点会成为 S3 的方法学优势。

## 3. 干扰类型设计（建议首版用前两类）

| 类型 ID | 名称 | 构造依据 | 难度 |
|---|---|---|---|
| **D1** | `same_class_wrong_instance` | **外观相似但对象不符**：同类别、不同实例 | 易，可自动 |
| **D2** | `topic_related_but_unsupportive` | **主题相关但不能支持答案**：同场景/同 aspect，但属于其它题目的 GT | 易，可自动 |
| D3 | `same_source_other_object` | 同 `source`（如都来自 Imagenet）但不同 `image_type` | 易，可自动 |
| D4 | `near_duplicate_view` | 同对象的**不同视角**，但视角不匹配本题所需 | 中，需图像相似度 |
| D5 | `hard_negative_from_retrieval` | 我方检索器的高分但非 GT 的图 | 中，依赖 S1-b |

**首版建议只做 D1 + D2**，因为：
- 完全可自动化、可复现；
- 不依赖检索器（可先于我完成）；
- 且**正好对映"误导"的两种主要机制**：类别混淆 vs 主题混淆。

### D1 具体做法（示例）

```python
# 从同 image_type 的其它题目里取 GT 图作为干扰候选
# 例: 本题 gt 是 'silky_terrier'，则从其它 image_type=='Animal' 的题里
#     取非 terrier 类的 GT 图，优先取同一 source
```

**注意**：`answer` 字段是细粒度类别名（实测第一条 `answer='silky_terrier'`，
选项 A/B/C/D 也都是 terrier 品种）。所以 D1 可以做得**很精准**：
取「同为犬类但品种不同」的图，正是"外观相似但对象不符"。

### D2 具体做法

从**同 `scenario`（或同 `aspect`）的其它题目**的 GT 图中取样，
这样图像在"主题/视觉风格"上相关，但不支持本题答案。

## 4. 必须满足的硬约束

1. **不得含正确证据**：干扰集与本题 `gt_images` 的 sha256 交集必须为**空**。
   逐题自动校验，结果写入 `contains_gt=false` 字段；**任何一题为 true 就整体退回重建**。
2. **不得含查询图本身**：与 `image` 的 sha256 也不得相同。
3. **数量匹配 S1**：S1 定稿是 5 张就 5 张（Incomplete 按 S1 的规则）。
4. **尺寸/预处理规则匹配 S1**：不额外缩放，交由各模型自己的 `image_processor`。
   但要在索引里记录原始 `w`/`h`，以便你在结果里报告输入像素。
5. **跨题不重复使用同一张干扰图**（同一题内也不重复）。
   全局记录干扰图使用次数，避免某张图被过度复用导致统计相关。
6. **顺序处理**：干扰图送入顺序建议**随机但固定种子**（seed 写入版本号），
   避免"干扰图总在末位"这种位置混杂因素。**随机种子必须记录**。

---

## 5. 记录规范（每题的每条干扰证据）

| 字段 | 含义 |
|---|---|
| `qid` / `raw_id` | 题标识（含原始 ID 映射） |
| `evidence_id` | `mragb:<id>#dis<rank>` |
| `path` | 相对路径 |
| `sha256` | **内容哈希**（用于校验不含 GT） |
| `order` | 送入模型的实际顺序 |
| `distractor_type` | `same_class_wrong_instance` / `topic_related_but_unsupportive` / ... |
| `source` | 取自哪道题的哪张 GT（`mragb:<src_id>#gt<k>`）——**可追溯** |
| `construction_rule` | 构造规则的文字描述 + 版本号 |
| `contains_gt` | **必须为 false**（自动校验结果） |
| `w` / `h` | 原始像素 |
| `seed` | 采样随机种子 |

**干扰标记仅用于分析，不透露给模型**：
`distractor_type` / `source` / `contains_gt` **绝不进入 prompt**。
建议实现上让「构造干扰集」与「组装 prompt」是两个模块，
prompt 组装函数**只接收图片列表和题目文本**，从接口上杜绝泄漏。

## 6. 需要单独设条件的情况（按你的要求）

| 条件 ID | 含义 | 说明 |
|---|---|---|
| `S3-pure` | **纯干扰**（首版） | 全部证据为干扰图，不含任何 GT |
| `S3-mixed` | **正确证据混入干扰图** | 例如 1 张 GT + 4 张干扰；**必须单独设条件、单独报告** |
| `S3-noisy` | 干扰 + 部分相关 | 可选，需要更细的难度分层 |

`S3-mixed` 的价值在于能测**「正确证据能否抵抗干扰」**，
但要明确它的 GT 数量（是 1 张还是全部），否则与 S2 不可区分。
建议 `S3-mixed` 用 **(1 GT + 4 干扰)**，并记录 GT 的位置顺序（因为位置可能影响结果）。
