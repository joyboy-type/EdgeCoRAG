# 五、S3 干扰证据实验：承担 + 构造规范（修订版）

## 0. 结论：**方便承担，我接。**

| 环节 | 负责 |
|---|---|
| 干扰候选挖掘与筛选 | 我 |
| **近重复 + 语义抽查（含无法确定的标记）** | 我 |
| 图片落盘、ID、索引、哈希 | 我 |
| 干扰类型标注（仅用于分析） | 我 |
| 送入模型、评分、统计、错误分析 | 你 |
| 干扰标记**不透露给模型** | 双方共同保证 |

**前置依赖**：S3 需与 S1 的数量/预处理/顺序规则对齐，故 **S3 定稿在 S1 定稿之后**。

---

## 1. 实验条件

| 条件 | 含义 | 是否 Oracle |
|---|---|---|
| **S0** | 无外部证据 | 否 |
| **S1** | 所有模型使用**同一组**检索证据 | 否 |
| **S2** | GT 正确证据（诊断能力上限） | ✅ **是，只能作上界** |
| **S3** | 错误/干扰证据（测是否被误导） | 否 |

**S2 的定位写死**：官方 README 明确「By default, use rag means use ground-truth rag examples」，
所以 S2 是**理想条件上界**，不是可部署方案。

---

## 2. ⚠️ 实测事实与其**有限的**用途

实测：官方候选中存在与 GT 字节相同的图，任意命中率 **55.9%**、rank-0 **32.6%**、
全部 GT 覆盖仅 **2.3%**。

**用途（仅限）**：作为 S1 条件的**描述性统计**随结果报告。

**不可用途**：

- ❌ 不可据此断言官方候选池"泄漏答案"——无法区分正常检索命中与使用标注生成
  （详见 [`official_pool_provenance.md`](official_pool_provenance.md)）。
- ❌ **对 S3 的用途也很有限**：它只说明"存在字节完全相同的图"，
  **不能**说明"其余图都不含支持信息"。见 §4。

**对 S3 真正有用的地方**：我们**确切知道哪些图是 GT**，所以能自动剔除
"与 GT 字节相同"的图。但**这只排除了字节级同一**，不排除近重复与语义支持。

---

## 3. 干扰类型设计

| 类型 ID | 名称 | 构造依据 | 首版 |
|---|---|---|---|
| **D1** | `same_class_wrong_instance` | 外观相似但对象不符：同类别、不同实例 | ✅ |
| **D2** | `topic_related_but_unsupportive` | 主题相关但不能支持答案：同场景/同 aspect，取自其它题的 GT | ✅ |
| D3 | `same_source_other_object` | 同 `source` 但不同 `image_type` | 备选 |
| D4 | `near_duplicate_view` | 同对象不同视角，视角不匹配所需 | 备选 |
| D5 | `hard_negative_from_retrieval` | 我方检索器高分但非 GT | 依赖 S1-b |

### ⚠️ 关键警示：D1/D2 **不自动等于"无支持信息"**

**"不同实例"或"来自别题"只是构造来源，不是"不支持答案"的证明。** 反例：

- 题目问"这只动物是什么品种"，一张**同科不同种**的图可能仍**缩小了答案范围**
  （排除法），甚至若选项里就含该类，反而**提供了支持信息**；
- 取自别题的 GT 图，若两题**共享同一对象或同一场景**，可能直接支持本题；
- 因此 **D1/D2 的每一条候选都必须做语义抽查**，不能靠构造规则盖章。

---

## 4. 校验要求（三层，缺一不可）

先前只做哈希不重叠是不够的——**哈希不重叠只证明没有相同字节**。

| 层 | 检查 | 判定 | 失败处置 |
|---|---|---|---|
| **L1** | 与本题 `gt_images` 及查询图的**字节哈希**交集为空 | 必须为 0 | 剔除 |
| **L2** | **近重复检查**（dHash 汉明距离，阈值见 `03_证据规则.md` §4） | ≤6 需人工看 | 剔除或标记 |
| **L3** | **语义抽查**：人工判断该图是否可能支持本题答案 | 三态标记 | 见下 |

### L3 三态标记（**不得默认通过**）

| 标记 | 含义 | 计入 |
|---|---|---|
| `verified_unsupportive` | 已人工确认为不支持 | 可计入"已确认干净" |
| `verified_near_duplicate` | 已确认近重复/同图 | **剔除** |
| `undetermined` | 未做抽查，或抽查无法判定 | **必须计入报告，不计入"已确认干净"** |

**"纯干扰"集只有在 `undetermined = 0` 时才能声称已确认。**
若抽查后仍有不确定项，报告里必须写："N 条未能确定，已标记，未从结果中剔除"。

### L2 的已知漏检

dHash 对**旋转、大幅裁剪、水平翻转不敏感**，且**同类不同实例图不会被判为近重复**
——而后者恰是 D1 的主要形态。所以 **L2 通过 ≠ L3 通过**。

---

## 5. 硬约束

1. **L1 必须为 0**：与本题 GT / 查询图字节哈希交集为空。
2. **数量与 S1 对齐**：S1 是 5 张就 5 张。Incomplete 按 S1 的规则（官方协议下为 1 张）。
3. **预处理与顺序规则与 S1 对齐**；顺序**随机但固定种子**，种子写入版本号。
4. **跨题不重复使用同一张干扰图**；记录全局复用次数分布。
5. **GT 辅助构造的 S3 标记为离线受控诊断**，**不当作可部署检索**。
   若构造过程用到了 GT 标注（例如"剔除了与本题 GT 相同的图"），
   必须在产物中显式标注 `used_gt_annotation_for_construction=true`。
6. **正式证据未完成时明确状态**，不承诺已冻结。

## 6. 记录规范（每题每条）

| 字段 | 含义 |
|---|---|
| `qid` / `raw_id` | 题标识（含原始 ID 映射） |
| `evidence_id` | `mragb:<id>#distractor<rank>` |
| `path` / `sha256` / `w` / `h` | 文件与内容哈希 |
| `order` | 送入模型的实际顺序 |
| `distractor_type` | D1 / D2 / ... |
| `source` | 取自哪题哪张（可追溯） |
| `construction_rule` | 规则描述 + 版本号 |
| `contains_gt_bytes` | L1 结果，**必须 false** |
| `near_dup_max_hamming` | 与本题 GT/查询图的最大相似度（L2） |
| **`semantic_verdict`** | `verified_unsupportive` / `verified_near_duplicate` / `undetermined` |
| `seed` | 采样随机种子 |

**干扰标记仅用于分析，不透露给模型**：`distractor_type` / `source` /
`semantic_verdict` **绝不进入 prompt**。实现上让「构造干扰集」与「组装 prompt」
是两个模块，prompt 组装函数**只接收图片列表与题目文本**。

## 7. 需单独设条件的情况

| 条件 ID | 含义 | 说明 |
|---|---|---|
| `S3-pure` | **纯干扰**（首版） | 全部为干扰图；需报告 `undetermined` 计数 |
| `S3-mixed` | **正确证据混入干扰图** | 建议固定为 **(1 GT + 4 干扰)**，并记录 GT 位置 |
| `S3-noisy` | 干扰 + 部分相关 | 可选，需更细难度分层 |

## 8. 交付物

```
freeze/S3_pure_distractor_v1/
├── manifest.jsonl            逐题干扰证据列表（字段见 §6）
├── evidence_index.csv        evidence_id ↔ 文件 ↔ sha256 ↔ 尺寸
```

`validation_report.json` 必须包含：

```json
{
  "questions": 0,
  "L1_contains_gt_bytes": 0,
  "L2_near_duplicate": 0,
  "L3_verified_unsupportive": 0,
  "L3_verified_near_duplicate": 0,
  "L3_undetermined": 0,
  "claim": "仅在 L3_undetermined == 0 时可声称已确认为纯干扰"
}
```

## 9. 需要你确认

1. **S3 首版范围**：是否只做 D1 + D2？（我建议是，但两者都需 L3 语义抽查）
2. **可接受的 `undetermined` 比例**：语义抽查成本高，是否允许一定比例的
   `undetermined` 并单独报告？还是要求必须为 0 才发版？
3. **Incomplete 在 S3 里单独报告**：该场景命中率仅 6.9%，几乎天然是"干扰条件"，
   混进 S3 总分会产生混淆。我建议**单独报告**。
