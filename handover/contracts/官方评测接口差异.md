# ⚠️ 官方评测代码接口差异与缺陷（实测，会影响评分）

> 我逐行读了 `mragbench/MRAG-Bench`（commit `4ae2241fdc5a`）的评测代码，
> 发现**三处**需要在 B 侧处理的问题。**这直接影响你评分的正确性与可复现性**，
> 请务必在跑正式实验前决定处理方式。

---

## 缺陷 1 ⛔ `parse_multi_choice_response` 第 3 参数类型错误（会崩溃）

**位置**：`eval/score.py:45`

```python
ans_idx_mapping = {'a': 0, 'b': 1, 'c': 2, 'd': 3}
out = parse_multi_choice_response(out, ['A', 'B', 'C', 'D'],
                                  ans_idx_mapping[item['gt_choice'].lower()])
#                                 ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 传进去的是 int
```

**函数签名与实现**：`eval/utils/automatic_extract.py:23`

```python
def parse_multi_choice_response(response, all_choices, index2ans):
    ...
    if len(candidates) == 0 and len(response.split()) > 5:
        for index, ans in index2ans.items():      # ← 第 36 行: int 没有 .items()
            ...
    elif len(candidates) > 1:
        ...
        index = response.lower().rfind(index2ans[can].lower())   # ← 第 58 行: int 不可下标
```

`index2ans` 的语义按函数自身用法应当是 **`{'A': 选项文本, 'B': ...}` 这样的字典**，
但调用方传了**整数**。

### 触发条件（两种，都不是罕见情况）

| 触发条件 | 后果 |
|---|---|
| 模型输出**不含可解析的选项字母**且 **词数 > 5** | `AttributeError: 'int' object has no attribute 'items'` |
| 模型输出**命中多个选项字母**（如"A 和 B 都不对"） | `TypeError: 'int' object is not subscriptable` |

### 为什么这很重要

官方 README 说：
> For most models, our automatic pipeline can handle the answer extraction job.
> However, in cases when gpt based answer extraction is needed, please set your openai api key.

也就是说**官方认为自动抽取能覆盖大多数情况**，但代码实际会在上述情况直接抛异常，
而不是优雅地回退到 GPT 抽取。**用官方脚本复现数字时，结果取决于模型输出恰好没触发这个 bug**
——这是不可复现的。

### 建议处理方式（**请你确认**）

1. **不要直接运行官方 `score.py`**。
2. 实现 `fixed_v1` 抽取器：修正 `index2ans` 为字典（`{'A': A文本, 'B': B文本, ...}`），
   与官方**意图**一致，同时保持"括号形式优先、多候选取最后出现者"的原有规则。
3. **同时保留**官方原始抽取结果，报告两者差异有多少题。
4. 在结果行的 `extraction_method` 字段标注用了哪一个（schema 已预留该字段）。

这样既不掩盖官方问题，也保证我们的数字可复现。

## 缺陷 2 ⛔ 字段名不一致：`qs_id` vs `id`

**位置**：

| 文件 | 行为 |
|---|---|
| `eval/models/llava_one_vision.py:78` | 写出的字段是 **`qs_id`** |
| `eval/score.py:38` | 读取的是 **`gt_choice`**、`item['output']`、`item['prompt']`、`item['scenario']` |
| `eval/score.py` | **从未使用 `id` 或 `qs_id`** |

后果：score.py **不报错但也不做逐题对齐**——它是**按行顺序**取 `gt_choice` 与 `output` 的
（第 36–58 行纯顺序遍历，无 ID 匹配）。
→ **一旦你的结果文件缺行、乱序或多行，准确率会静默算错**，且没有任何校验。

**建议**：结果行里**同时**带上 `id`、`qs_id`、`raw_id`（schema 已预留），
并且我们**自己的评分脚本必须按 ID 对齐**，不依赖行顺序。

## 缺陷 3 ⚠️ 提示模板的图片占位符数量写死

**位置**：`eval/utils/dataloader.py:46,48`

```python
# 常规: 6 个占位符 = 查询图 + 5 张证据
prompt = f"... {image_placeholder}{image_placeholder}{image_placeholder}{image_placeholder}{image_placeholder}{image_placeholder}\n"
if scenario == 'Incomplete':
    # Incomplete: 2 个占位符 = 查询图 + 1 张证据
    prompt = f"... {image_placeholder}{image_placeholder}\n"
```

**含义**：官方**只支持 5 张证据**（Incomplete 为 1 张）。
如果你要试 **top-3** 或其它数量，**必须同步改占位符数量**，
改了之后**就不再与官方数字可比**。

**建议**：把占位符数量作为**参数化**的（`n_slots = 1 + k`），
并在每条结果里记录 `protocol_version` 与 `prompt_image_slots`。
不同 k 的结果**分表报告**。

### 附带发现：README 与默认参数的差异

- README 说「By default, use rag means use ground-truth rag examples.」
- `eval/models/run_model.sh` 实测：`--use_rag True --use_retrieved_examples False`
  → 确实默认走 **GT 证据**，不是检索证据。

所以：**用官方 retrieved 池需要显式加 `--use_retrieved_examples True`**，
否则你跑出来的其实是 S2（GT 上界），不是 S1。**这个坑很容易踩。**

## 附：评测输入/输出的正确契约

### 官方 `score.py` 期望的输入行字段

| 字段 | 必需 | 说明 |
|---|---|---|
| `gt_choice` | ✅ | `'A'/'B'/'C'/'D'` |
| `output` | ✅ | 模型原始输出（会被抽取） |
| `prompt` | ⚠️ | 仅当自动抽取失败、需 GPT 兜底时用 |
| `scenario` | ✅ | 分场景统计用 |

> 注意：**不是** `id`、**不是** `qs_id`、**不是** `prediction`。

### 官方 `score.py` 的输出

```json
{
  "Overall": 59.35,
  "Angle": ..., "Partial": ..., "Scope": ..., "Occlusion": ...,
  "Temporal": ..., "Deformation": ..., "Incomplete": ..., "Biological": ..., "Others": ...
}
```

**注意 key 顺序列表里有 `Occlusion`，但数据集实际场景名是 `Obstruction`**
（`score.py:96-107` 的 `key_order`）。这会导致 `Obstruction` 场景**被静默丢弃**：
`ordered_outputfile` 只保留 `key_order` 里存在的键，
而 `outfile` 里存的是 `Obstruction`，于是**它不会出现在最终 json 里**。

→ **这是第四处需要修正的地方**：分场景汇总时不要把场景名映射写错。

### 实测场景名（请以此为准，共 9 种）

```
Angle, Partial, Temporal, Others, Obstruction, Scope, Deformation, Biological, Incomplete
```
