|---|---:|---|

## 1. 判定矩阵（字段 → 三种假设各应出现什么）

| 字段 | H1 同图多实例（不去重） | H2 唯一内容但保留副本 | H3 含额外语料 | 区分力 |
|---|---|---|---|---|
| `index.entries` | **14,475** | 4,712 ~ 14,475 之间 | **≈18,955** | ★★★（H1 直接排除 B 的 18,955） |
| `dedup.by_identity` | `false` | `true` | 任意 | ★★★（H2 要求 true） |
| `dedup.kept_duplicates` | 14,475−4,712=**9,763** | **0** | 0 | ★★★ |
| `counts.unique_contents` | **4,712** | 4,712 | **> 4,712（很可能 18,955）** | ★★★ |
| `sources[].length` | 2（题目 + 语料） | 2 | **≥3，且含非 HF 数据集的一条** | ★★★（H3 的唯一直接证据） |
| `row_order.rule` | `question_order` / `insertion_order` | `sha256_asc` | `insertion_order`（原始语料顺序） | ★★ |
| `identity.rule` | 任一 | `sha256_*` | 可能与我们不同（原始字节 / 别的重编码） | ★ |
| `dtype.storage` / `compute` | 不影响判定 | 不影响 | 不影响 | ✗（解释"当时为什么能跑"，不参与假设区分） |
| `corpus_encode.batch_size` | 同上 | 同上 | 同上 | ✗ |

> `dtype` / `batch` 之所以没有区分力：它们只解释"数值为什么会动"，不解释"条目数为什么多"。

## 2. 条件性排除（**前提未满足前不算结论**）

若 B 按 `contracts/index_receipt_field_mapping.md` 填值，即
`index.entries = 18,955`、`dedup.by_identity = true`、`dedup.kept_duplicates = 0`、`counts.unique_contents = 18,955`，则：

- **H1 被结构性排除**：18,955 ≠ 14,475，且"不去重"得到的不可能是 18,955 个互不重复的身份。
- **H2 被结构性排除**：去重后仍保留 18,955 条，说明索引里确有 18,955 个**互不相同**的图像，不是副本。
- **只剩 H3**：这 18,955 张里有 **14,243 张不在** A 侧可复现的 4,712 个唯一内容中。

但 **H3 自身还未成立**——它需要 `sources[]` 里那一条"额外语料"给出 **sha256 + 规模**，能对上 14,243（或至少解释其来源）。**在 `sources[]` 到位前，本文件仍不下结论**，只写"条件性排除 H1/H2"。

## 3. 判定所需的最小字段集（缺任一条 → 写"数据不足以判定"）

1. `index.entries`（硬数字）
2. `dedup.by_identity` + `dedup.kept_duplicates`
3. `counts.unique_contents`（是 4,712 还是 18,955，一句话定 H1/H2 vs H3）
4. `sources[]` 的**条数**与**每条 sha256 及规模**（H3 的直接证据）
5. `row_order.rule`（解释并列次序与"逐行一致"的可行性）
6. `identity.rule`（若与我们不同，则 H3 更可能，且两批不可配对）

## 4. 三种假设下 A 的后续动作与**禁止表述**

| 假设 | `verdict` | A 的后续动作 | 禁止表述 |
|---|---|---|---|
| H1 | `matches_instances` | 可逐题配对；差异按"实例 vs 内容"解释 | 不能说"索引多了 4,480 张新图" |
| H2 | `matches_unique` | 可配对；按内容对齐 | 不能把"条目多"当成"图多" |
| H3 | `matches_neither` | **只能做机制分析**；两批排名/分数**不得进同一张表**；`a21` 每题附索引口径告警 | 不能说"同一索引下复现"、"拓扑一致" |

## 5. 与逐题归因（`a21`）的关系

- `verdict = matches_neither` 时，`a21` 会在每题输出里附 `caveat`：即使数值特征匹配某一类（dtype / 归一化 / 解码 / 批组成），也**不能排除索引成分差异**，该归因只能写成"候选类"。
- `verdict = matches_instances | matches_unique` 时，`a21` 的逐题归因才是完整结论。
