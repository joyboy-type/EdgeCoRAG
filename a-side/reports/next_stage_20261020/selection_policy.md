# 维度与策略选择准则（selection_policy v1）

日期：2026-10-20。对应审阅补充 A4。**只补选择流程，不改接口**：top-k=10、select-k=3、候选身份、排序键、归一化口径全部不变，因此协议串仍是 **`a-side/retrieval-interface-v1`**，36 个产物哈希不变（见 `a-side/retrieval_if_v1/verify.json`）。

## 1. 这份准则解决什么

`dim_evidence_protocol.md` 只写了"维度只用 dev_150 选"，没有给指标、并列处理、以及 `order_fragile` 题怎么办。而 dev_150 上 128 维的 `order_fragile` 高达 **0.92**、768 维 0.85，选择极易被排序脆弱性带偏。下面把它写死。

## 2. 两层决策

### L1：检索层筛选（dev_150，只用检索指标，不需要生成）

- **主指标：`any-hit@10`**（是否至少命中一张精确 GT）。理由：它是"下游有没有机会看到 GT"的必要条件，且对分母不敏感（分母固定 150）。
- **等价带（预注册）**：两维度的 `any-hit@10` 命中题数差 ≤ **1 题**（即 ≤ 0.0067 绝对比例）时，视为并列，不声称任一维度"更好"。
- **并列时的次序键**（逐级比较，前一级相同才看下一级）：
  1. `set_recall@10` 高者优先（GT 覆盖更全）；
  2. `MRR@10` 高者优先（首个命中更靠前）；
  3. **维度更小者优先**（同样的质量下选更省内存/更快的一侧）；
  4. 仍相同 → 取较小维度（保证确定性，不依赖实现顺序）。
- 参考实现与数据：`a-side/retrieval_if_v1/metrics/retrieval_metrics_by_dim.csv`。

**dev_150 现状（供 L1 参考，不是最终选择）**

| 维度 | any-hit@10 | set_recall@10 | MRR@10 | order_fragile |
|---:|---:|---:|---:|---:|
| 768 | 0.7400（111/150） | 0.4420 | 0.5000 | 0.847 |
| 512 | 0.7333（110/150） | 0.4420 | 0.4989 | 0.793 |
| 256 | 0.7333（110/150） | 0.4340 | 0.4897 | 0.853 |
| 128 | 0.7267（109/150） | 0.4113 | 0.4600 | 0.920 |

按本准则：768 与 512/256 的 any-hit@10 差 ≤1 题 → 落在等价带 → 看 set_recall@10（768=512=0.4420 > 256）→ 再比 MRR@10（768 最高）→ **L1 倾向 768**。但这只是检索层结论，**不得据此直接定档**；L2 必须用 dev 上的生成结果。

### L2：下游层定档（B 在 dev_150 上做生成与评分）

- 指标：`strict_choice_v1` 准确率（固定分母 150，格式失败计错）。
- **等价判定**：同模型、同题的配对 bootstrap 95% 区间跨 0 → 视为并列；此时按 **L1 的次序键**决定。
- 只允许"4 个维度在同一 dev_150、同一模板、同一模型"下比较；不同模型/不同 prompt 的维度结果不得互相借用。
- 最终只有胜出的维度进 `frozen_test`，跑**一次**。

## 3. `order_fragile` 题怎么处理（写死，不许临场决定）

- 定义：`min_adjacent_margin < 1e-3`（与 `pool_quality/*__margins.csv` 一致；该档实测翻序率 13.4%，更小档 40%+）。
- **主分析一律不剔除**：分母保持 150 / 1033。剔除 fragile 题会同时改变分母并偏向"数值上高保真"的题，属于事后选样。
- **必须分层报告**：`fragile` 与 `non-fragile` 两层的指标与差值都要给，并注明各层题数。
- **一致性规则**：若同一比较在两层里符号相反（例如 fragile 层 128 更好、non-fragile 层 768 更好），结论写 **"未解决"**，不选维度；此时默认沿用 768（主条件）并说明原因。
- 禁止：只报某一层；用剔除 fragile 后的分母冒充主结论；把 fragile 比例当成维度优劣的证据（它只说明数值可复现性）。

## 4. 硬边界

| 允许 | 禁止 |
|---|---|
| 在 dev_150 上用检索指标做 L1 筛选 | 用 `frozen_test` 的任何指标参与选择 |
| 在 dev_150 上用生成准确率做 L2 定档 | 在 frozen 上试多个维度后挑最高 |
| 报告分层的 fragile 结果 | 剔除 fragile 题后重算主表 |
| 并列时按 §2 次级键决定 | 声称某维度"更优"（在等价带内） |
| 用 `internal_holdout` 做技术联调？ | **禁止**：它已用于 v1.10.1 结论，不得再当选择集 |

## 5. 选择结果表必须包含的字段

`dim, n, any_hit@10, set_recall@10, MRR@10, accuracy(strict_choice_v1), fragile 分层两行, 选择依据（落在等价带/超出等价带）, 选择时使用的数据集（只能是 dev_150）, 协议串, 产物 sha256, 决策日期`

## 6. 与其它协议的关系

- 本准则不改变 `interface_freeze.md` §2–§6 的任何口径；若将来要改 top-k / select-k / 排序键 / 抽样种子，按 `interface_freeze.md` §9 升 **v2** 并重新生成 `artifacts.json` 与 `verify.json`。
- 本准则也不改变 `routing_protocol_v2.md` §3 的纪律（同一份纪律的细化，不是替代）。
- 若 B 认为 L1 主指标应换成 `set_recall@10`，需在**跑 dev 生成之前**书面提出并在本文件升版；跑完之后再改指标视为事后选择。
