# 路由与成本协议（routing_and_cost_protocol.md）

日期：2026-10-17。**只定义含义、成本口径与边界，不跑路由。**

## 1. 四条路径

| 路径 | 含义 | 证据 | 占位符 |
|---|---|---|---|
| **A0** | E2B 直接（无检索） | 无（仅查询图） | 1 |
| **A1** | 检索 + E2B | 待定（官方 top-3 或自主重检索 top-k） | 1+k |
| **A2** | E4B 直接（无检索） | 无 | 1 |
| **A3** | 检索 + E4B | 同上 | 1+k |

**本机限制**：E4B 在 8 GB 显存不可行（4bit 加载即占 8.69 GiB），A2/A3 需更大显存机器；
跨硬件耗时不具可加性（见 §4）。

## 2. Oracle 路由矩阵（仅上界，不可部署）

**定义**：对每题，在**已执行的四条路径**中选「质量最大且满足预算」的路径，
作为可达到的上界。

| 项 | 说明 |
|---|---|
| 输入 | 离线已保存的四路径真实结果（正确性 + 各路径成本） |
| 输出 | 每题的最优路径选择（Oracle 上界） |
| **边界** | **只能用离线真实结果算上界**；**不得**依赖题目答案、其它路径实际输出或测试标签做「可部署选择器」 |
| **与 S2 的区分** | S2 是「GT 证据 Oracle」（给了正确证据的上界）；Oracle 路由是「路径选择 Oracle」（给了正确路径的上界）。**两者不是同一概念**，不得混称 |

**结论使用**：若 Oracle 相对最优固定路径的改进不足以抵消路由成本，或路径互补性极低，
按任务书 Gate A1 停止设计路由器。

## 3. 成本口径（索引构建与在线成本分开）

### 3.1 离线（索引构建，单列）

| 项 | 说明 |
|---|---|
| 语料下载 | 字节数、来源 revision |
| 编码建索引 | 总图像数、编码器耗时、峰值显存 |
| 索引文件 | 类型（flat/IVF/HNSW）、体积、驻留方式 |
| **不得混入在线查询时间** | 任务书硬性要求 |

### 3.2 在线（每题，热启动测 3 次取中位数，另报冷启动）

| 项 | 字段 |
|---|---|
| 查询编码 | `encoder_ms` |
| 检索 | `retrieval_ms` |
| 选择/路由 | `router_ms` |
| 生成 | `generation_ms` |
| 索引驻留 | 索引是否常驻、常驻显存 |
| 切换（A0↔A1↔A2↔A3） | 冷/热切换开销，单列 |

CUDA 计时前后 `torch.cuda.synchronize()`。

## 4. 跨硬件边界（不能相加）

- A 旧 4060（8 GB）与 B 旧 4090 的耗时**不得直接相加成实测端到端**。
- 每行结果必须带 `hardware` 字段（gpu/vram/driver）。
- 需要拼接的端到端数字，必须在**同一硬件**上按同一协议重测。
