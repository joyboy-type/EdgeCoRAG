# 跨栈声明（cross_stack_statement_20261021）

日期：2026-10-21｜性质：**只做声明与依据列举，不开机、不报价、不承诺替代执行**

## 0. 一句话结论

**A 侧的 `0/1203`（fp32 下查询批大小 16→1 的排序差异为零）是"A 栈内的性质"，不能作为 B 栈的结论；跨栈是否一致只能由持有该 GPU 的一方，在其**独占 GPU、固定 CPU 线程、固定 dtype 与 TF32 设置**的条件下，用 `a18` 跑出回执来证明。`a18` **不支持索引复用**，每次复核都**必然重新编码整份语料**，因此它不是"轻量校验"，而是一次完整编码作业。**

## 2. 由此推出的三条操作性结论

1. **跨栈复核的代价 = 一次完整语料编码 + 一次查询编码。** A 栈实测 fp32 编码 4,712 图 ≈ **26 min**（0.33 s/图，RTX 4060 Laptop）；B 栈的 bf16/torch 2.8 组合**没有实测**，不能套用 A 的数。
2. **谁跑：由持有目标 GPU 的一方跑，且必须独占。** 理由：`a18` 的产物是"该栈上是否改序"，而改序与否直接受并发占用、CPU 线程、cuDNN 算法选择影响；共享 GPU 或后台有负载时，这份回执不能代表该栈。
3. **两栈结果不可互相推导。** A 栈 `changed_order=0` 不能推出 B 栈也是 0；B 栈若 `stack_sensitive`，也不能反过来说 A 栈的冻结协议失效——它只说明"该栈必须按固定 rank 列表消费"。

## 3. 同机成本实验的执行主体与条件（不含"谁来付费"）

| 项 | 要求 |
|---|---|
| 执行主体 | **独占该 GPU 的一方**（当前为 A/B 各自的会话，不交叉代替） |
| 硬件 | 同一台机器内完成"查询编码 + 检索 + 证据选择（含 utility 前向）+ 生成"的串联；不得跨机拼接分段耗时 |
| GPU 状态 | 独占，无其他进程占用；计时前后 `torch.cuda.synchronize()` |
| CPU 线程 | `OMP_NUM_THREADS` 固定为合法值，并把**实际生效值**写进 `hardware.cpu_thread_env`（该字段缺失/非法会直接抛错） |
| 精度 | dtype 与 TF32 设置写进回执；与冻结协议不一致时必须显式标注 |
| 样本量 | 每题 ≥3 次测量 + 1 次预热（预热不进统计）；**观测数 <20 不报 P95** |
| 资源指标 | 整卡显存 / 系统 RAM / 能耗只能由外部实测注入（`rec.resources()` / `attach_resources()`）；**allocator 峰值不得改名为整卡指标** |

## 4. 明确不承诺的事

- **不承诺 B 侧可替代执行 A 侧的同机成本实验**：两栈不同（torch 2.11/2.8、Pillow 12.3/11.3、tv 0.26/0.23），且 `a18` 不支持复用索引，替代执行得到的既不是 A 栈的数、也不是 B 栈可比的数。
- **不承诺无报价开机**：任何一次 `a18` 全量复核（≈26 min 起）+ 任何一次同机端到端串联，都需要先给出时长、费用上限、硬停机时间与保全方案。
- **不承诺"跑通即等价"**：`stack_invariant` 只说明"该栈上批大小不影响排序"，不说明两栈数值相同、也不说明下游答案一致。

## 5. 一句话交接口径（可直接引用）

> 我们在 A 栈（torch 2.11.0 / torchvision 0.26.0 / Pillow 12.3.0 / numpy 2.5.2，fp32、TF32 关闭）上实测：查询批大小 16→1 的 top-10 顺序变化为 **0/1,203**。该结论**仅适用于该栈**；跨栈一致性由目标栈一方以同一协议运行 `a18` 产出回执后判定（判定阈值：`changed_order=0` **且** `changed_set=0` 才可称一致，否则须注明"A 栈结果不能外推"并列出改序题号与最大分差）。`a18` 每次运行都重新编码整份语料，不支持索引复用。
