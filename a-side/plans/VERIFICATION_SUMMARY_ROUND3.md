## 2. 一处必须报告的口径不一致（Incomplete 的 S1 vs S2）

S1 在 Incomplete 上取 **3 张**（用户指定），S2 在 Incomplete 上只有 **1 张**
（用户指定保留真实数量）。

**后果**：同一场景（Incomplete）下 S1/S2 的图片数不同，故 Incomplete 的
S1–S2 差距**不能纯归因于证据质量**（数量也是变量）。

已写入每个包的 `package_meta.json` 的 `known_mismatch` 字段，并标注
`needs_confirmation=true`。这是**口径本身的技术后果**，非实现错误；
最小修正建议：分析 Incomplete 时单列，或在 S2 的 Incomplete 上另做
「仅取首张 vs 取全部」的敏感性说明（不改变主口径）。

## 3. S3 纯干扰集（D1）

构造规则（可辩护，非猜测）：
> 来源题 s 的 GT 图**由数据集人工标注为「描绘 s 的答案」**；若 s 的答案
> （规范化后）等于目标题 q 的某个**错误选项**，则 s 的 GT 图描绘的是
> **q 的错误类别** —— 即 D1「外观相似但对象不符」。

三层校验：

| 层 | 检查 | 结果（全量 4 split） |
|---|---|---|
| L1 字节去重 | 候选 sha ∉ q 查询图/GT | 排除 63 |
| L2 近重复 | 候选 dHash 与查询图汉明 > 6 | 排除 0 |
| L2b **组内去重** | 最终 3 张之间字节/近重复 | **已修复为 0**（§5） |
| L3 语义三态 | **待人工** | 见下 |

### ⛔ 语义审核：A 侧无法完成，正式 S3 子集为空（诚实声明）

**当前模型不支持图像输入**，A 侧**无法查看图片**，因此**无法执行语义审核**
（含模型辅助审核）。据此：

- semantic_review.csv 中的 semantic_verdict 是**自动构造规则的初判**，
  **不等于语义审核**，不得当作审核完成。
- 每个 S3 包已生成 
eview_checklist.csv（人工审核清单，三态留空待填）。
- **审核步骤与判据见 -side/plans/S3_REVIEW_GUIDE.md**。
- 在人工审核完成前，**正式 S3 子集为空**；「满 3 张」只是候选范围，不是已审核题数。

**语义三态**：
- 支持（图片支持正确答案，剔除）/ 不支持（确认不支持，进入纯干扰）/
  无法判断（排除，不标为纯干扰）。
- **不设置任何"允许 X% 未知"门槛**：无法判断的题不是"允许"，是"排除并单列"。

## 4. 规范化匹配的修正

首版按精确字符串匹配错误选项，覆盖率仅 40%。实测发现数据集答案/选项
存在**大小写与下划线不一致**（`silky_terrier` vs `Silky_Terrier`），
精确匹配漏掉合法候选。改为**规范化匹配**（小写 + `_`→空格）后覆盖率升至 50%。
规范化是**格式对齐**，不是内容虚构。

## 5. 本轮修的三个实现问题

| 问题 | 修复 |
|---|---|
| S3 查询图声明了路径但未写盘 | 查询图实际写入每个包 |
| S3 审核只记录保留候选 | 记录**全部**候选（含被排除的无法判断/字节重复/近重复） |
| 验收的 task_payload 隔离用值子串匹配，误报 "marigold"/"golden retriever" | 改为**按 key 检查**（仅 `question`+`choices`，choices 四键齐全） |

## 6. 已知限制（随结论报告）

1. S3 D1 覆盖率有限（~50%），因大量题的错误选项不在任何其它题的答案中出现
   （描述行为题、寿命区间题、独特车型/品种等）；**这是数据属性，非构造缺陷**。
2. S3 语义判定是构造保证，非逐张人工看图；`无法判断` 已排除。
3. 图片为 JPEG q95 重编码产物（原始字节取不到），哈希与落盘字节同源。
4. Incomplete 的 S1/S2 图片数不同（见 §2）。
5. 实体/同源相关性未能隔离（数据集 2688 个图片哈希跨题共享）。
