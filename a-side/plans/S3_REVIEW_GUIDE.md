# S3 语义审核指南（人工审核，必须由人完成）

> **关键前提**：A 侧当前模型**不支持图像输入**，无法查看图片，
> 因此**无法执行语义审核**（包括模型辅助审核）。
> 本指南把审核交给能看图的人（B 或总部），并给出精确步骤。
> **自动构造规则 ≠ 语义审核**；在人工审核完成前，**正式 S3 子集为空**。

---

## 0. 现状（诚实的阶段划分）

| 阶段 | 状态 |
|---|---|
| 候选生成（自动构造规则：来源题 GT 图标注为其答案 == 目标题错误选项） | ✅ 已生成 |
| 字节去重 / 近重复（对查询图、全部 GT、最终 3 张之间） | ✅ 已做（确定性脚本） |
| **语义三态审核（支持/不支持/无法判断）** | ❌ **未完成，待人工** |
| 正式 S3 子集（只含人工确认「不支持」且满 3 张的题） | ❌ **空，待审核后产生** |

## 1. 需要审核什么

对每个 S3 包的 `review_checklist.csv`，逐行判断：
「这张干扰图，是否**支持**目标题的正确回答？」

- **支持**：图片能帮助回答正确（例如描绘了正确类别、泄漏了答案信息）→ 剔除。
- **不支持**：图片不会帮助回答正确（例如描绘的是错误选项类别）→ 可进入纯干扰集。
- **无法判断**：无法确定（如区域图可能通过对比帮助排除）→ 排除，不标为纯干扰。

**判据**：结合目标题题干、四个选项、正确选项、以及干扰图内容综合判断。
**不能**仅凭"来源题答案是错误选项"就判定不支持——那只是构造规则，不是审核。

## 2. 审核步骤（审核者）

1. 打开 `packages/<split>_s3/review_checklist.csv`。
2. 逐行：
   - 看 `question` + `choices_A..D` + `correct_choice`，明确"支持正确答案"的含义；
   - 看 `distractor_image_path` 指向的图片，结合 `source_question`（来源题的上下文）；
   - 在 `semantic_verdict` 填 `支持` / `不支持` / `无法判断`；
   - 在 `review_basis` 填判定依据（一两句话，例如"图描绘的是 Yorkshire 犬，非题目所问 silky 犬，故不支持"）；
   - 在 `reviewer` 填审核者 ID，`reviewed_at` 填时间。
3. 完成后，统计：某题 3 张**全部**为「不支持」→ 该题进入正式 S3 子集；
   任一为「无法判断」或「支持」→ 该题排除（不足 3 张，单列）。

## 3. 产出（审核后）

- `review_checklist.csv`（已填写版）→ 审核记录，可追溯到 qid / final_evidence_id / 来源 / 依据。
- 一个**合格子集清单**：列出"3 张全部不支持"的 qid，供 B 在相同题目上比较 S1/S3。

## 4. 工具与局限（审核时须知）

- A 侧已完成：字节去重（sha256）、近重复（dHash 汉明 ≤6）—— 对查询图、全部 GT、
  最终 3 张之间均做。**dHash 局限**：对旋转、大幅裁剪、水平翻转不敏感，会漏检近重复。
- 上述检查是**辅助**，不能替代人工看图。
- **任何自动标签（`semantic_review.csv` 里的 `semantic_verdict`）都是初判，
  不得当作审核完成**。正式结果以 `review_checklist.csv` 的人工填写为准。

## 5. 需要的参与

- 需要**能查看图片的人**（B 或总部）执行 §2 的审核。
- A 侧提供：候选包、审核清单、步骤、可追溯字段。
- A 侧**不提供**：任何声称"已完成语义审核"的结论。
