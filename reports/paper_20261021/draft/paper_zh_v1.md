## 一、引言

多模态检索增强生成（RAG）的常见承诺是：给模型配上外部视觉证据，就能弥补模型自身视觉知识的不足。这个承诺隐含两个前提——检索能把正确证据找出来，模型能把找到的证据用上去。本文不预设这两个前提成立，而是把它们拆开测量。

我们研究一个受限但可穷尽的问题：**在同一套冻结的检索接口与同一批题目上，外部视觉证据对小型与中型多模态模型的增益到底有多大，边界在哪里。** 为此我们固定五个模型（Gemma 4 E2B / E4B、Qwen3-VL 4B / 8B、Qwen3.5 4B）、四种证据条件（无检索 S0、共享检索 S1、GT 证据 S2、干扰证据 S3 子集）、一个冻结的图文检索器（EmbeddingGemma-2，fp32、TF32 关闭、固定 revision），在 MRAG-Bench 的 1,353 题冻结测试集上做配对比较。

结果与"检索有益"的直觉相反，且这种相反本身是分层的：

**第一层，官方共享检索基本无益，甚至有害。** 相对无检索基线，S1 的准确率变化在五个模型上分别为 −2.52、−0.29、−0.87、+2.90、+0.97 个百分点 `[T2.qwen3vl_4b.S1_minus_S0_pp]` `[T2.qwen3vl_8b.S1_minus_S0_pp]` `[T2.gemma4_e2b.S1_minus_S0_pp]` `[T2.gemma4_e4b.S1_minus_S0_pp]` `[T2.qwen35_4b.S1_minus_S0_pp]`。也就是说，把官方候选的 top-3 图像交给模型，在四个模型上没有带来可辨认的改善，其中三个模型反而下降。

**第二层，正确证据是有效的。** 把数据集标注的 GT 图像直接给模型，S2 相对 S0 的提升为 +6.39 至 +10.36 个百分点 `[T2.qwen3vl_4b.S2_minus_S0_pp]` `[T2.qwen3vl_8b.S2_minus_S0_pp]` `[T2.gemma4_e2b.S2_minus_S0_pp]` `[T2.gemma4_e4b.S2_minus_S0_pp]` `[T2.qwen35_4b.S2_minus_S0_pp]`。证据本身有用，问题出在"找到它"这一步。

**第三层，检索命中率构成硬上限。** 在 1,033 题的配对分析集中，GT 图像进入 top-3 的题目只有 516 题，未进入的有 517 题 `[retrieval.top3_miss]`。这 517 题在任何模型上都不可能因为检索而受益。

**第四层，命中之后仍有模型差异。** 在命中的 516 题里，答对题数从 Gemma 4 E2B 的 219 题到 Qwen3-VL 8B 的 343 题 `[T3.gemma4_e2b.命中且答对]` `[T3.qwen3vl_8b.命中且答对]`，即同样的证据，利用率从约 42% 到约 66%。这部分差异才是"模型会不会用证据"，与检索质量无关。

据此，本文的结论是一个边界而不是一个方法：**在没有可部署路由与实测成本的条件下，多模态 RAG 的收益上界主要被检索命中率与模型利用率这两项决定，而不是被"是否接一个检索器"决定。**

本文的贡献有三点。其一，一套冻结协议与失败保留规则：解析失败、生成失败、预算耗尽一律计错并保留分母，不重试、不替换。其二，把"命中"与"答对"交叉成 2×2 分格（未命中但答对 / 未命中且答错 / 命中但答错 / 命中且答对），使检索质量与证据利用率在同一个表里可分离；检索伤害作为独立 overlay 单列，不与四格相加。其三，一次跨栈可复现性检验：在同一语料、同一查询集上，batch 16 与 batch 1 两次编码的排序完全一致（1,203 题零翻转 `[a18.changed_order]`），说明该检索接口在换栈后仍然可用。

我们也明确不主张的事情：本文给出的 post hoc Oracle 上界（相对最佳固定策略 +8.5 至 +10.6 个百分点）不是可部署收益；本文未验证任何路由策略；本文的成本测量只覆盖三个模型、20 题、每请求 2 个 token 的短答案场景，不能外推为完整成本。

## 二、相关工作

**多模态 RAG 与共享检索。** MRAG-Bench 提供以视觉为中心的评测协议与 1,353 道选择题，并在同一批数据上区分"直接回答"与"给定候选证据"两种条件，这与本文的 S0/S1 划分直接对应。VisDoM 与 MMDocRAG 把视觉富文档问答扩展到多页、多文档场景，其数据形态与本文的多图候选设置不同，本文仅把它们作为外部验证与后续工作，不在其上主张语义准确率。

**候选证据的选择与效用。** Utility-MRAG 提出对候选证据做效用排序再交给生成模型，是本文最直接的方法对照。本文没有复现其 surrogate 选择器：本文使用的 utility 定义为 `ℓ("True")` 的原始 logit `[utility.completed]`，与作者使用的打分形式在数学上不等价（作者形式对候选取 softmax，本文对单 token 取原始 logit），因此本文只能主张"形式相同"，不能主张"复现了作者的 utility"。

**路由与成本。** RAGRouter 研究按查询把问题分配给不同规模的 RAG 模型，其前提是存在可学习的路由信号与可测量的路径成本。本文的 Gate 裁决显示：虽然 post hoc Oracle 相对最佳固定策略存在 +8.5 至 +10.6 个百分点的空间 `[gate.qwen3vl_4b.delta_pp]`，但该空间基于事后选优、且路由成本未实测，因此本文把路由判定为证据不足，而不是据此提出路由方法。

**输入污染与鲁棒性。** V-QPP 研究查询侧图像预处理对检索的影响。本文的 S3 干扰子集是这一方向的小规模补充（AI 图像辅助、label-aware），规模有限，不足以支撑鲁棒性结论，故只作诊断报告。

**可复现性与身份口径。** 复现研究中一个常被忽略的问题是"同一个数在不同发布物里指代不同对象"。本文在索引口径上遇到了这类问题：历史发布索引 18,955 行与其原始字节哈希，与本研究语料的 4,712 唯一内容并非同一口径；按字节求交后重合 4,282 张 `[index.intersection_q95]`，本研究语料另有 430 张不在该索引内（其中 415 张为查询图、15 张为 GT）`[index.live_absent]`。本文的处理方式是全文只用一套口径做定量陈述，另一套只在脚注中出现。

## 三、协议与测量

### 3.1 数据与分割

主数据为 MRAG-Bench，公开测试集 1,353 题。开发与评估的切分一经确定即冻结：150 题用于选择固定策略（cosine / random / utility 三种证据选择方式）与维度，1,033 题作为评估集，选择过程不接触评估集标签。评估集上每模型每条件的分母恒为 1,033 `[T1.qwen3vl_4b.S0.n]`，解析失败、生成失败、预算耗尽一律计错并保留在分母内。

### 3.2 条件定义

- **S0（无检索）**：模型只看到问题与原图，不接收外部证据。
- **S1（共享检索）**：所有模型看到完全相同的一组 top-3 图像与相同顺序，证据来自同一个冻结检索器与同一个快照。
- **S2（GT 证据）**：直接给数据集标注的正确图像，作为能力上界，不是可部署路径。
- **S3（干扰子集）**：在已批准的小规模子集上替换为干扰或近重复图像，仅作诊断。

S1 与 S2 的证据数不同（S1 为 3 张，S2 通常为 5 张、个别为 1 张），这一差异会影响解释，因此两条件的比较只用于"检索质量 vs 证据质量"的定性区分，不用于同一分母下的因果推断。

### 3.3 检索接口

检索器为 EmbeddingGemma-2，固定 revision `914f7f89142e33e77833254d9c9b90c3cef7303b`，fp32 计算、TF32 关闭、float32 层重新归一化；排序使用 `lexsort(-score, identity)`，先剔除查询图自身再取前 k。该接口在本研究的 4,712 唯一内容语料上运行，语料由数据集原始字节解码后按 JPEG q95 重编码得到，因此语料身份是"重编码字节"口径。

跨栈一致性检验：在相同语料与 1,203 个查询上，batch 16 与 batch 1 两次编码得到的排序完全一致，`changed_order = 0`、`changed_set = 0`、`changed_top3 = 0` `[a18.changed_order]` `[a18.changed_set]` `[a18.changed_top3]`，判定为 `stack_invariant`。这说明该接口的排序结果不依赖批大小，换栈后不必重测排序。

### 3.4 身份口径与索引

本文区分三个数：历史发布索引 18,955 行、本研究语料 14,475 个图像实例、4,712 个唯一内容。三者不是同一口径，不可互换。按原始字节求交，18,955 与 4,712 的重合为 4,282 张 `[index.intersection_q95]`；本研究语料中有 430 张不在该索引内 `[index.live_absent]`，其中 415 张为查询图像、15 张为 GT 图像 `[index.absent_GT]`。正文中一切语料规模与检索指标的定量陈述只用 14,475 与 4,712；18,955 仅以"历史发布索引行数"出现。

### 3.5 统计

配对比较以题为单位，按 564 个 query–GT 图像关联分量做 bootstrap 重采样，10,000 次，seed 42，区间为描述性、未预注册。多重比较上同时报告未校正区间与 Holm 兼容的保守矩形（数值上等于 Bonferroni），并注明其局限。跨零一律表述为"不能排除无差异"，不写成"无差异"；描述性区间不用于证明普遍因果。

### 3.6 测量

在线测量采用逐请求记录：每个（模型 × 条件）的首个请求单独标记为冷启动，随后 warmup 不少于 3 次，热请求报告 P50 与 P95。分段耗时记录预处理、查询编码、检索、生成与端到端五项；索引驻留分别记录 CPU RSS 与 GPU 显存增量；设备级峰值用 `nvidia-smi` 轮询采样，与 `torch` allocator 峰值分开报告；模型切换逐次计时。语料编码属离线成本，与在线延迟分开统计，不混入 P95。

本文的成本测量范围为三个模型（Gemma 4 E2B、E4B、Qwen3-VL 4B）、20 题、每请求生成 2 个 token 的短答案场景。该范围决定了成本结论只能作为 pilot 陈述，不能外推为完整回答或全部模型的成本曲线。
