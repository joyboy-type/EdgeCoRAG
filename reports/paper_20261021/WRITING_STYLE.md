# 写作风格参考：同类多模态 RAG 论文的特征与我们该模仿什么

对象：`张.docx` 指定的六篇（MRAG-Bench ICLR'25、MMDocRAG NeurIPS'25 D&B、VisDoM NAACL'25、Utility-MRAG ACL'26、VQQP ICML'26、RAGRouter NeurIPS'25），
以及同赛道常见写法。结论用于约束我们自己的稿子。

## 一、这些论文的共同结构

**1. 摘要：五句结构**

几乎所有篇都遵循同一模板，顺序固定：

```
① 现状（现有做法/基准关注什么）
② 缺口（但存在 X 场景/问题没被覆盖）
③ 我们做了什么（提出/构建/评测 + 规模数字）
④ 主要发现（带具体数字，通常 2–3 个）
⑤ 意义/可用性（代码开源、基准公开）
```

MRAG-Bench 就是标准样本：先讲现有基准只看文本知识 → 视觉知识场景被忽略 → 提出 16,130 图 / 1,353 题 / 9 场景 → 所有 LVLM 用图比用文本提升大，但 GPT-4o 用上 GT 只涨 5.82% 而人类涨 33.16% → 结论是"该基准能推动利用证据的能力"。

**我们要学的**：摘要里必须有一个**反直觉的具体数字**（我们的是 "four of five models 的 S1−S0 区间跨零" 和 "命中率 50%"）。

**2. 引言：五段式 + 三条贡献**

```
段1 背景与重要性
段2 现有工作的做法与不足（点名 2–4 篇）
段3 我们的思路/本文做什么
段4 主要结果（数字）
段5 贡献列表（通常 3 条，bullet）
```

贡献列表的写法高度模板化：`(i) We introduce ... (ii) We conduct ... (iii) We release ...`。
**注意：顶会论文的贡献条目几乎都带"可交付物"**——数据集、基准、代码、评测协议，而不只是"我们发现"。

**3. 相关工作：按主题分组，每组 2–4 句，最后一句点差异**

常见四组：数据集/基准、检索与证据选择、路由与成本、鲁棒性/预处理。每组结尾必须有一句"与本文不同之处"。

**4. 方法/基准章：先形式化，再讲实现**

- 先给符号（数据集 D、查询 q、候选池 C、评分函数 s）
- 再给流程（编号步骤或算法框）
- 然后给实现细节（模型 revision、解码参数、prompt 模板）
- **实现细节通常放附录**，正文只留影响复现判断的部分

**5. 实验章：表先于文**

顶会经验论文的典型顺序：

```
表1：主结果（模型 × 条件），最好的加粗
   ↓ 一段逐条解读（三个 takeaway，每条一个数字）
表2：消融/分析
   ↓ 一段解释为什么
图1：某个关键趋势
```

**每一段几乎都以数字开头**（"Table 1 shows that ... improves by 3.2 points"），而不是以论断开头。

**6. 必有的"分析"节**

六篇里五篇都有单独的 Analysis / Discussion 小节，做的是：错误分类、按场景分层、案例研究。**这是审稿人判断"作者有没有真的看过数据"的地方。**

**7. 限制与伦理**

- ACL/EMNLP：`Limitations` 必写、独立成节、不计页；
- NeurIPS（含 D&B）：`Broader Impact` / ethics 段落；
- 都在正文末尾、参考文献之前。

## 二、表格与图的惯例

| 惯例 | 说明 |
|---|---|
| 主表竖线不用、横线三线 | booktabs 风格 |
| 最佳值加粗 | 次佳常加下划线 |
| 表注写清分母与条件 | "n = 1,033 per cell" |
| 图字号 ≥ 8pt、黑白可读 | 我们 F4 已按这个做 |
| 每个数字必须有单位与方向 | "+3.2 pp" 不是 "3.2" |

## 三、这类论文的"修辞"特征（很重要）

1. **从不说"显著"除非有检验**。经验论文里 "significantly" 出现频率很低，多数写 "improves by X points"。
2. **负结果必须配解释**。如果某条件变差，一定要给出机制猜测并标注为猜测。
3. **对比对象要公平**。方法论文会明写"在同一预算下"；基准论文会明写"所有模型用同一 prompt"。
4. **可复现性当成卖点**，不是负担：模型 revision、prompt 原文、评测脚本都放附录。

## 四、我们该像谁、不该像谁

| 篇 | 类型 | 我们是否模仿 |
|---|---|---|
| MRAG-Bench | 基准 + 大规模评测 | **结构上最接近**：借鉴它的"条件对比 + 大表 + 反直觉数字" |
| MMDocRAG | 数据集 + 新指标 | 部分：借它的"指标定义要单独讲清" |
| VisDoM | 系统 + 数据集 | 不模仿（我们不做系统） |
| Utility-MRAG | 方法 | 不模仿（我们不做方法） |
| RAGRouter | 方法 | 不模仿 |
| VQQP | 基准 | 部分 |

**关键差异**：我们是一篇**审计/边界**论文，不是基准也不是方法。所以：

- 贡献不能写成"提出 X"，只能写"我们测量/拆解/发布协议"；
- 必须有**明确的负面结论**，并且用区间语言（"cannot exclude no difference"）；
- 必须解释"为什么这个负结果有价值"——通常的写法是给出一个**可量化的上界**（我们的 Oracle +8.5–10.6 pp）作为"空间在哪"的证据。

## 五、具体到我们的稿子：写作检查表

- [ ] 摘要含一个反直觉数字 + 一个规模数字
- [ ] 引言五段、贡献三条、每条含可交付物（协议 / 2×2 分解 / 身份对账 / 成本 pilot）
- [ ] 相关工作四组，每组末句点差异
- [ ] 方法章先符号后流程，实现细节进附录
- [ ] 结果章每段以数字开头，三个 takeaway
- [ ] 有独立 Analysis 节（2×2 + 利用率 + 伤害）
- [ ] Limitations 独立成节、八条
- [ ] 每个数字带单位与方向，且能追到 `frozen_numbers.json` 的 id
- [ ] 参考文献页码与 DOI 已核（未核的写会议+年份）
- [ ] 附录含 prompt 原文、完整表、复现命令
